Review completed work and verify quality before committing.

## Usage

```
/done
```

---

## Step 1 — Diff 재검토

변경된 파일 전체를 다시 읽는다. 구현 중 놓친 부분이 없는지 확인한다.

---

## Step 2 — 불변 제약 점검

`.claude/rules/core-constraints.md`의 5개 제약을 순서대로 확인한다.

- [ ] **읽기 우선** — 파악 없이 작성된 코드가 없다
- [ ] **패턴 준수** — 기존 패턴에서 이탈한 곳이 없다
- [ ] **정책 보존** — 비즈니스 규칙·운영 정책을 임의로 변경하지 않았다
- [ ] **최소 변경** — 요청 범위 밖의 파일을 수정하지 않았다
- [ ] **스코프 준수** — 의도치 않게 수정된 파일이 없다

위반 항목이 있으면 ADAPT: 원인을 파악하고 수정 후 Step 1부터 재시작한다.

---

## Step 3 — 품질 게이트

```bash
npm run typecheck
npm run test
```

오류가 있으면 수정 후 Step 2부터 재시작한다.

---

## Step 4 — 결과 보고

다음 형식으로 출력한다.

```
수정 파일:
  - (파일 경로) — (변경 내용 한 줄)

건드리지 않은 레이어: (목록)

점검 결과: 통과 / 주의 사항 (있으면 명시)
```

모두 통과하면 커밋 준비가 완료된 것이다.
