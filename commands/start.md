Understand the task context before writing any code.

## Usage

```
/start <작업 설명>
```

---

## Step 1 — GROUND: 관련 코드 탐색

작업 설명에서 수정이 필요한 도메인과 레이어를 식별하고, 관련 파일을 읽는다.

탐색 순서:
1. 작업 설명에 언급된 파일·도메인부터 시작
2. types → mapper → service → store → component 순으로 연결 추적
3. 비슷한 구현이 프로젝트 내에 이미 있는지 확인
4. 정책 함수·공유 유틸이 영향을 받는지 확인

이 단계에서는 파일을 읽기만 한다. 수정하지 않는다.

---

## Step 2 — 복잡도 판단 (S / M / L)

`.claude/rules/core-constraints.md`의 S/M/L 기준으로 작업 규모를 분류한다.

- **L이면**: 서브태스크로 분해하고 처리 순서를 제안한다
- **M이면**: 수정할 레이어와 순서를 명시한다
- **S이면**: 영향 파일과 변경 요약만 확인한다

---

## Step 3 — 계획 보고

다음 형식으로 출력하고 사용자 확인을 기다린다. 확인 전에 코드를 수정하지 않는다.

```
규모: S / M / L

관련 파일:
  - (파일 경로) — (한 줄 역할 설명)

작업 순서:
  1. (레이어 또는 파일)
  2. ...

주의 사항:
  - (정책 영향, 공유 의존, 확인 필요 항목 등)
```

> 작업 완료 후에는 `/done`으로 품질 게이트를 통과하고 커밋한다.
