# 핵심 제약 — 모든 작업에 적용

## 원칙

**코드베이스가 스승이다.** 기존 코드에는 보이지 않는 이유가 있을 수 있다.  
구현 전에 반드시 읽는다. 관찰한 패턴을 따른다.

---

## 불변 제약 (작업 유형과 무관하게 항상 적용)

1. **읽기 우선** — 파악 없이 쓰지 않는다. 관련 파일을 먼저 읽는다.
2. **패턴 준수** — 더 좋아 보여도 기존 패턴을 따른다. 개선은 별도 제안한다.
3. **정책 보존** — 비즈니스 규칙·운영 정책 관련 코드를 건드릴 때는 먼저 확인한다.
4. **최소 변경** — 요청 범위 밖은 손대지 않는다.
5. **스코프 준수** — 작업 완료 후 범위를 이탈하지 않았는지 자가 확인한다.

---

## 사고 모델

```
GROUND → APPLY → VERIFY
  ↑                 ↓
  └──── ADAPT ←─────┘  (검증 실패 시만)
```

### GROUND (파악)

관련 코드를 읽고, 패턴을 관찰하고, 영향 범위를 파악한다.

- 구현 전에 반드시 거친다
- 기존 패턴을 찾고 기록한다
- 정책 함수·공유 유틸 영향 여부를 확인한다

### APPLY (구현)

GROUND에서 관찰한 패턴을 따라 구현한다.

- 기존 코드 스타일과 맞춘다
- 요청 범위만 수정한다
- 불변 제약을 의식하며 작성한다

### VERIFY (검증)

완료 후 스스로 점검한다.

- 불변 제약 5개 위반 없음
- `npm run typecheck` 통과
- 요청 범위 이탈 없음

### ADAPT (재조정)

VERIFY 실패 시만 실행. 원인을 파악하고 GROUND부터 재시작한다.

---

## 작업 규모 분기 (S / M / L)

작업 시작 전 규모를 분류하고, 규모에 따라 GROUND 깊이를 조정한다.

| 규모 | 기준 | GROUND 범위 | 처리 |
|------|------|------------|------|
| **S** | 파일 1~2개, 명확한 변경 | 해당 파일만 읽기 | GROUND → APPLY 바로 |
| **M** | 단일 도메인, 여러 레이어 | 도메인 전체 파악 | 전체 단계 수행 |
| **L** | 여러 도메인 또는 정책 함수 포함 | 전체 탐색 | 서브태스크 분해 후 진행 |

> **L 작업**: 한 번에 구현하지 않는다. 서브태스크로 쪼개고 각각을 M/S 규모로 처리한다.
